# 오류 기록

실제로 겪은 오류와 원인, 해결 방법을 적습니다.
같은 오류가 다시 나면 여기서 찾아보세요. 최신 항목이 아래에 옵니다.

- 버전별 변경 내용은 [CHANGELOG](../CHANGELOG.md)에 적습니다.
- 설계상의 고민은 [고민과 결정](decisions.md)에 적습니다.

## 새 오류 쓰는 법

오류가 나면 **화면에 나온 문구를 그대로** 복사해서 "증상"에 붙여 넣으세요. 원인은 몰라도 됩니다. 나중에 채우면 됩니다.

```
## E-000. 한 줄 요약
- 날짜: YYYY-MM-DD
- 어디서: 폰 앱 / 노트북 앱 / 브라우저 / 빌드 / 설치 / 네트워크
- 버전: (예: PM 테스트 0.3, Phone Mirror 1.0.1)
- 증상: (나온 문구 그대로, 무엇을 하다가 났는지)
- 원인:
- 해결:
- 상태: 해결됨 / 진행 중 / 우회 / 제약(못 고침)
```

## E-001. 연결 실패 10060 — 폰이 다른 Wi-Fi에 있었음
- **날짜:** 2026-11-25
- **어디서:** 네트워크 (초기 스크립트)
- **증상:** `연결 실패: cannot connect to 192.168.1.21:36349: ... (10060)`. 한글 부분은 깨져서 나옴(E-002).
- **원인:**
  - 10060은 "응답 시간 초과"라는 뜻입니다. 처음 페어링한 Wi-Fi(5G_36)와 지금 Wi-Fi(5G_39)가 달라서 폰 IP가 `.21`에서 `.7`로, 포트도 바뀌어 있었습니다.
  - 노트북 ARP 표에서 `.21`이 `Incomplete`로 나와, 그 주소를 쓰는 기기가 없다는 걸 확인했습니다.
- **해결:** 같은 Wi-Fi에서 무선 디버깅을 다시 켜고 새 주소(`192.168.1.7:38027`)로 연결했습니다. 그 뒤 mDNS 자동 찾기를 넣어, 주소가 바뀌어도 알아서 찾게 했습니다.
- **상태:** 해결됨

## E-002. adb 한글 오류 메시지가 깨짐
- **날짜:** 2026-11-25
- **어디서:** 노트북 스크립트 (PowerShell 5.1)
- **증상:** `?곌껐??援ъ꽦?먯쑝濡쒕????묐떟???놁뼱 ...`
- **원인:** adb는 UTF-8로 출력하는데, PowerShell은 한국어 기본 코드페이지(CP949)로 읽었습니다.
- **해결:** 스크립트 시작에 `[Console]::OutputEncoding = [Text.Encoding]::UTF8`를 넣었습니다. 스크립트 파일 자체도 UTF-8(BOM)으로 저장해야 PowerShell 5.1에서 한글이 깨지지 않습니다.
- **상태:** 해결됨

## E-003. Phone Mirror가 폰과 연결 안 됨 — 10061
- **날짜:** 2026-11-25
- **어디서:** 노트북 앱 Phone Mirror 1.0.0
- **증상:** 앱에서 폰을 찾지 못합니다. 진단해 보니 `cannot connect to 192.168.1.7:38027: 대상 컴퓨터에서 연결을 거부했으므로 연결하지 못했습니다. (10061)`
- **원인:** 폰은 같은 Wi-Fi에서 ping에 응답했지만, **무선 디버깅이 꺼져 있었습니다**. 갤럭시는 화면이 오래 꺼져 있거나, Wi-Fi가 잠깐 끊기거나, 재부팅하면 무선 디버깅을 자동으로 끕니다.
- **해결:**
  - 폰에서 무선 디버깅을 다시 켰습니다.
  - Phone Mirror 1.0.1에서 10061, 10060, unauthorized를 구분해 안내하고, 5초마다 자동 재연결하도록 했습니다.
- **상태:** 해결됨
- **구분법:** **10061 = 무선 디버깅 꺼짐**, **10060 = 폰이 응답 없음** (다른 Wi-Fi이거나 화면 꺼짐)

## E-004. 보안 위험 자동 차단을 켜면 무선 디버깅이 안 됨
- **날짜:** 2026-11-25
- **어디서:** 폰 설정 (삼성 One UI)
- **증상:** 자동 차단이 켜져 있으면 무선 디버깅(adb)을 쓸 수 없어, scrcpy가 연결되지 않습니다.
- **원인:** 자동 차단은 외부에서 폰을 제어하는 통로(adb)를 막는 보안 기능입니다. 정상적인 동작입니다.
- **해결:** scrcpy 방식으로는 피할 수 없습니다. 보안 기능을 우회하는 방법은 쓰지 않기로 했습니다. 대신 adb가 필요 없는 **직접 만든 폰 앱**으로 방향을 바꿨습니다(decisions D-008, D-011).
- **상태:** 제약 → 폰 앱으로 우회

## E-005. Play 프로텍트가 APK 설치를 막음
- **날짜:** 2026-11-25
- **어디서:** 설치 (PM 테스트 0.1)
- **증상:** 폰에서 APK 파일을 열어 설치하니 `기기 보호를 위해 앱이 차단되었습니다`가 나옵니다.
- **원인:** 구글 Play 프로텍트는 파일로 받은 앱이 접근성 권한을 요구하면 강하게 막습니다(보이스피싱 앱 대비).
- **해결:**
  - 자동 차단을 잠깐 끄고 무선 디버깅을 켭니다.
  - Phone Mirror의 **[APK 설치]**(adb install)로 설치합니다. adb로 설치하면 이 차단이 적용되지 않습니다.
  - 설치가 끝나면 무선 디버깅을 끄고 자동 차단을 다시 켭니다.
- **상태:** 우회 (앱을 고칠 때마다 이 설치 과정이 필요합니다)

## E-006. Kotlin 컴파일 오류 — 식 본문 함수에서 return
- **날짜:** 2026-11-25
- **어디서:** 빌드 (PM 테스트 0.1, `ProbeAccessibilityService.globalKey`)
- **증상:** `Returns are prohibited for functions with an expression body. Use block body '{...}'.`
- **원인:** `fun f() = performGlobalAction(when (...) { ... else -> return false })`처럼 `=`로 정의한 함수 안에서 `return`을 썼습니다.
- **해결:** `{ }` 블록 본문으로 바꾸고, `when` 결과를 변수에 담은 뒤 `return`했습니다.
- **상태:** 해결됨

## E-007. 빌드가 로그 없이 실패 — 'gradlew.bat' is not recognized
- **날짜:** 2026-11-25
- **어디서:** 빌드 (명령 실행 방식)
- **증상:** `exit=1`만 나오고 로그 파일에 `'gradlew.bat' is not recognized as an internal or external command`
- **원인:** PowerShell에서 `cmd /c`로 실행할 때 작업 폴더가 프로젝트 폴더가 아니었습니다.
- **해결:** PowerShell에서 `.\gradlew.bat`를 직접 실행하고, 출력을 변수로 받아 확인했습니다. Android 빌드는 `JAVA_HOME`을 Android Studio의 JDK(`C:\Program Files\Android\Android Studio\jbr`)로 맞춘 뒤 실행합니다.
- **상태:** 해결됨

## E-008. 앱 목록에서 Chrome, Play 스토어가 빠짐
- **날짜:** 2026-11-25
- **어디서:** 노트북 앱 Phone Mirror (개발 중 실제 폰으로 확인)
- **증상:** "별도 화면에서 앱 실행"의 앱 목록에 Chrome, Gmail, Play 스토어 같은 앱이 보이지 않습니다.
- **원인:** scrcpy `--list-apps`에서 `*`로 표시되는 시스템 앱을 기본으로 숨겼습니다. 그런데 갤럭시에서는 이런 기본 앱들도 시스템 앱입니다.
- **해결:** 기본은 전체를 보여주고, "직접 설치한 앱만" 보기 옵션을 따로 뒀습니다.
- **상태:** 해결됨

## E-009. 테스트 앱이 느리고 드래그가 너무 많이 됨
- **날짜:** 2026-11-25
- **어디서:** 폰 앱 PM 테스트 0.1 + 브라우저
- **증상:** 화면 반응이 느립니다. 드래그하거나 휠을 돌리면 생각보다 훨씬 많이 넘어갑니다. 로그에 `스와이프 취소됨`이 가끔 나옵니다.
- **원인:**
  - 느림: 화면 사진을 한 장씩 요청합니다(왕복 누적). JPEG는 CPU로 초당 15장만 만들고, 드래그는 마우스를 놓은 뒤에야 실행됩니다.
  - 드래그 과다: 짧은 시간에 그은 스와이프를 안드로이드가 "빠르게 튕김"으로 보고 관성(플링)을 줍니다.
  - 스와이프 취소됨: 앞 스와이프가 끝나기 전에 다음 스와이프가 오면 안드로이드가 앞의 것을 취소합니다.
- **해결:** PM 테스트 0.3에서 MJPEG 스트림, 실시간 드래그(continueStroke), 멈춘 뒤 놓을 때 100ms 정지, 휠 끝 정지를 넣었습니다(CHANGELOG 0.3).
- **상태:** 0.3에서 수정, **실제 폰에서 확인 필요**

## E-010. 코드 검토로 미리 찾은 버그 모음 (0.3 이전)
- **날짜:** 2026-11-25
- **어디서:** 폰 앱 PM 테스트 0.2 (설치 전 검토)
- **증상:** 실제로 겪지는 않았습니다. 독립 검토 6회에서 찾았습니다.
- **주요 내용과 해결 (모두 0.3에 반영):**
  - 드래그 중 휠이나 두 번째 클릭 → 손가락이 눌린 채 멈추고 모든 조작이 막힘 → 대기열 교착 해소
  - 드래그를 1~2초 하면 지연이 0.15~0.3초까지 쌓임 → 구간 50ms 제한, 추가 시간 보정
  - 멈춘 뒤 놓아도 관성이 생김 → 100ms 정지 후 떼기
  - 노트북이 절전하거나 Wi-Fi가 끊기면 손가락이 눌린 채 남음 → 5초 핑, 15초 시간 초과
  - Chrome이 MJPEG를 한 장 늦게 그림 → 다음 장 머리글을 미리 보내기
  - 캡처를 끌 때 앱이 죽을 수 있음(스레드 경쟁) → 캡처 스레드에서만 정리
  - 마지막 화면 누락, 회전 시 좌표 틀어짐, "앱 하나만 공유" 선택 문제 → 각각 수정
  - 브라우저 탭 두 개가 1초마다 조작권을 서로 빼앗음 → 밀려난 탭은 자동 재연결 중지
- **상태:** 0.3에서 수정

## E-011. 0.3에서도 속도가 아쉬움
- **날짜:** 2026-11-25
- **어디서:** 폰 앱 PM 테스트 0.3 + 노트북 브라우저
- **증상:** 0.1보다는 나아졌지만 여전히 반응이 느리게 느껴집니다. (어느 쪽이 느린지, 화면 장/초와 구간 추가 지연 숫자는 확인 중)
- **원인 (추정):**
  - JPEG 방식의 한계로 보입니다. 화면마다 약 3MB를 복사하고 CPU로 압축(장당 수십 ms)합니다.
  - 그 결과를 브라우저가 다시 디코딩해야 합니다.
  - 장 간격(30ms) 대기도 더해집니다.
  - scrcpy처럼 빠르려면 폰의 하드웨어 H.264 인코더가 필요합니다.
- **해결:** 브라우저 대신 노트북 앱에서 H.264를 해독하는 Linky를 새로 만들기로 했습니다 (decisions D-014, D-015).
- **상태:** Linky로 해결 시도 중 (실제 폰 확인 필요)

## E-012. Linky 0.1 첫 구현 검토에서 찾은 문제 39건
- **날짜:** 2026-11-26
- **어디서:** Linky 폰 앱과 노트북 앱 (설치 전 검토)
- **증상:** 실제로 겪지는 않았습니다. 독립 검토 4개(보안, 폰 영상, 노트북 영상·입력, 통신 규칙 일치)에서 찾았습니다.
- **주요 내용:**
  - **[높음] 페어링 숫자 맞추기:** 공격자가 노트북인 척 숫자 직전까지 갔다가 끊기를 2분 동안 수천 번 반복하면, 폰에 뜨는 숫자를 원하는 값에 맞출 확률이 생겼습니다. → 페어링 창 하나에 시도 한 번으로 바꿨습니다.
  - **인증 전 공격:** 같은 Wi-Fi의 아무 기기가 연결 칸 4개를 차지해 진짜 노트북을 막을 수 있었습니다. 16MB짜리 이름을 보내 폰 앱을 메모리 부족으로 죽일 수도 있었습니다. → 10초 절대 시한, 인증 전 8KB 제한, IP당 2개 제한, 이름 정리를 넣었습니다.
  - **자동 연결이 페어링 시작:** 노트북이 가짜 폰에 자동 연결해 페어링 창을 띄울 수 있었습니다. 인증서가 바뀐 경고도 가짜 폰이 보내는 값에 기대고 있었습니다. → 자동 연결은 페어링하지 않고, 인증서가 바뀌면 그 연결로는 페어링하지 않게 했습니다.
  - **영상 지연 누적:** Wi-Fi가 느려지면 보내기 버퍼에 몇 초 분량이 쌓였습니다. → 버퍼를 줄이고, 150ms 이상 밀리면 다음 키프레임까지 건너뛰게 했습니다.
  - **신원 파일:** 읽기에 실패하면 조용히 새로 만들어 모든 페어링이 끊겼습니다. → 다시 읽어 확인하고, 망가진 파일은 남기고 경고하게 했습니다.
  - **그 밖:** 막힌 쓰기가 공용 스레드를 멈춤, 연결이 끊겨도 노트북이 다시 연결하지 않음, 터치 좌표 1% 어긋남, 시계 오차로 연결 실패, 백업으로 개인 키가 나감 등
- **수정하지 않은 것:** 폰이 모든 네트워크(모바일 데이터, 핫스팟 포함)에서 연결을 받는 점은 그대로 둡니다. Wi-Fi에만 묶으면 폰 핫스팟으로 쓰는 경우가 막히고, TLS와 페어링이 이미 보호하기 때문입니다.
- **2차 검증 (7건, 모두 낮음):**
  - 삭제한 페어링이 이름 갱신 때 되살아날 수 있음
  - 세로 크기를 거부하는 인코더 크기 검사
  - 큰 키프레임 뒤 건너뛰기 반복
  - 지난 "페어링 중단" 알림이 남음
  - 노트북의 HELLO 대기 시한이 없음, 꾸며낸 PONG 처리
  - 이름이 같은 두 번째 폰을 페어링할 수 없음 (decisions D-016)

  → 모두 고쳤습니다. 화면이 멈췄을 때 영상이 갱신되지 않는 경우는 인코더의 100ms 반복 설정이 이미 막고 있어 그대로 둡니다.
- **상태:** 수정됨. 두 앱 빌드 성공. 노트북 앱은 가짜 폰 시험 통과. **실제 폰에서는 아직 확인하지 않았습니다.**

## E-013. 안드로이드 빌드에서 공유 코드를 못 찾음
- **날짜:** 2026-11-25
- **어디서:** 빌드 (Linky 폰 앱 뼈대)
- **증상:** `Unresolved reference 'protocol'.`
- **원인:** AGP 9의 내장 Kotlin은 `java.srcDir(...)`로 추가한 폴더의 `.kt` 파일을 컴파일하지 않았습니다.
- **해결:** `sourceSets { getByName("main") { kotlin.directories.add("../../shared/src/main/kotlin") } }`로 바꿨습니다.
- **상태:** 해결됨

## E-014. 컴파일 오류 — nullable VideoCapabilities 호출
- **날짜:** 2026-11-26
- **어디서:** 빌드 (Linky 폰 앱, 검토 수정 중 `VideoEncoder.kt`)
- **증상:** `VideoEncoder.kt:221:33 Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type 'MediaCodecInfo.VideoCapabilities?'.`
- **원인:** 인코더가 지원하는 영상 크기를 확인할 때, 값이 없을 수 있는(nullable) 객체를 바로 호출했습니다.
- **해결:** `caps?.isSizeSupported(w, h) != false`로 바꿨습니다. 정보가 없으면 일단 시도합니다.
- **상태:** 해결됨

## E-015. install.ps1 실행이 막힘
- **날짜:** 2026-11-26
- **어디서:** 설치 (노트북 PowerShell)
- **증상:** `.\android\install.ps1 : 이 시스템에서 스크립트를 실행할 수 없으므로 ... install.ps1 파일을 로드할 수 없습니다. ... PSSecurityException / UnauthorizedAccess`
- **원인:** Windows PowerShell의 기본 실행 정책(Restricted)이 .ps1 파일 실행을 막습니다.
- **해결:** 그 실행에만 정책을 풀어서 실행합니다: `powershell -ExecutionPolicy Bypass -File .\android\install.ps1`. 시스템 설정은 바꾸지 않습니다.
- **상태:** 우회
